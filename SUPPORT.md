# Getting help

Start with the [user guide](docs/USER_GUIDE.md),
[development setup](docs/DEVELOPING.md), and [known issues](docs/ISSUES.md).

Use [GitHub issues](https://github.com/LazaroHurtado/blueprint/issues) for
reproducible bugs, questions, and focused feature requests. Include the Blueprint
version/commit, OS and architecture, install method, expected/actual behavior, and
the smallest synthetic reproduction you can share. A screenshot of the problem is
helpful if it contains no account, repository, or credential information.

For save/recovery errors, copy the error message and preserve the original files.
Do not upload `transaction.json`: it contains old and new file contents. See
[recovery guidance](docs/USER_GUIDE.md#export).

For Copilot issues, distinguish Blueprint connection/model-list errors from
upstream account entitlement or organization policy. Never post tokens or raw
OAuth URLs. Use the account refresh control and the guidance in
[privacy and Copilot troubleshooting](docs/PRIVACY.md).

Vulnerabilities belong in [private security reports](SECURITY.md).
Conduct concerns use the [code of conduct](CODE_OF_CONDUCT.md).
This is a community-maintained project; responses and fixes are best-effort,
not a commercial support service or guaranteed SLA.
