## Dependency notices and sources

Run `npm run notices` before packaging. The generated `licenses/generated/`
directory contains:

- `npm.txt`: production frontend package copyright/license files.
- `rust.txt`: native dependency license texts and exact-version source links,
  generated by the pinned `cargo-about` tool.
- `manifest.json`: input and output hashes tying those files to the dependency
  locks and pinned runtime version.

Release builds refuse missing or stale generated notices. Installers include
this document, Blueprint's license, upstream notices, and generated notices.
On Ubuntu these are installed in the package's `/usr/lib` resource directory
(use `dpkg -L blueprint` to locate them); on macOS they are
inside `Blueprint.app/Contents/Resources/`. Inspect the actual candidate bundle
before publishing; do not distribute a bare executable without its notices.

Some native dependencies use MPL-2.0. They are unmodified dependencies, not
relicensed Blueprint code. Their exact versions and source repositories are
identified by `Cargo.lock` and the generated native notices; sources are available
from the linked crates.io version pages, including the published source archives.
If modifying an MPL-covered dependency, satisfy its source-availability obligations
and update the corresponding release notices before distribution.

Ubuntu's GTK/WebKit and other system packages are supplied by the operating
system, not copied into Blueprint's Debian package. They retain their own
licenses. Repackaging as a self-contained image requires a separate review of any
system libraries copied into that image. The candidate workflow deliberately
builds Debian packages and macOS application bundles, not AppImages.

See [licenses/README.md](licenses/README.md) for upstream provenance and
[release preparation](https://github.com/LazaroHurtado/blueprint/blob/main/docs/RELEASING.md)
for the redistribution review gate.
